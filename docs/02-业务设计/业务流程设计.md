# 业务流程设计

版本：V1｜整理日期：2026-10-08｜用途：当前工程交接；非客户正式验收。

用户先以自然语言或明确对象选择提出问题。系统读取当前数据版本和有效会话，再由模型提取对象、集合、条件、所问属性和输出动作。程序校验来源、字段、单位及关系，明确请求直接查询；仍有歧义时保留草稿，每次只问一个必要业务问题。

|流程|输入与结果|状态边界|
|---|---|---|
|明确查询|当前问题及对象→执行结果和业务口径|通过完整核验后执行；模型计划不等于结果|
|补答澄清|待补原任务+短答→补齐槽位|保留其他条件；第三轮短答续接仍需分析|
|切换对象/对象域|新标识或“那构型呢”→新范围|当前完整新标识不能被历史主体覆盖；候选不能自动选中|
|多任务|2–4项独立问题→分项答案|子任务编号和来源分开；不支持任意跨任务依赖|
|分页/依据|结果编号+页码→展示完整集合的一页|不重新缩小统计范围，不将首屏当全集|
|新对话/恢复|新会话或签名续问→独立状态|浏览历史与可执行状态分开；签名失效须新建查询|
|导入|CSV预览→明确提交→新快照|共享数据整体切换，清空旧会话；不是普通只读查询|

无匹配是合法执行后集合为空；未查、缺数据、不支持、计划无效、模型不可用是不同状态。业务反馈和系统错误分开呈现，不能以0条替代失败。当前接口和页面仍可能没有忠实完成输出动作，须按第三轮原问句检查任务是否真正结束。
