# 业务规则设计

版本：V1｜整理日期：2026-10-08｜用途：当前工程交接；非客户正式验收。

|规则|确定性处理|实现定位|
|---|---|---|
|对象域明确|同码不同树不自动合并；未限定字段的identity与显式name/code分开|object_scope、request_contract、data|
|父子关系|按真实父字段遍历，直接与全部后代分开；导入拒绝环路|data.Store及ancestors|
|部件与所有对象|类型筛选与层级编号分开，子设备不计为部件|attributes.CATALOG、analytics|
|记录与编码|测点原始行与不同编码数分别统计，多来源并列|data、data_context|
|报警条件|已报警按状态；开启且已报警再加开关条件；原因非空不等于已报警|query_filters、data_context|
|空值和数字|空值不补0，文本不参与数值比较，Decimal保留精度|typed_fields、attributes|
|单位|明确原话和原值核验，不从“度”或编码猜物理量，不任意换算|request_contract、typed_fields|
|阈值|真实、估计、变化速率偏差各高低三级，共18项；只投影所问或明确全部|attributes、typed_fields|
|时间与时长|原始测量时间保留；1970不擅自纠正；无事件起止不算持续时长|data、属性目录|
|统计|只允许登记字段和group_count/ratio；完整集合计算后分页|analytics|
|失败状态|不得更新为已执行成功的主体/条件，不伪造空结果|app、business_request.commit_state|

名字含TMP与编码含TMP是不同查询。当前原CSV中前者0条、测量点编码后者737条；这说明需核对实际字段，不说明自然语言应自动把名称改成编码。数值最高、最早、两点差值等输出动作不因取到原始列表就自动完成。

规则出处是当前原始字段和已实现契约；需要改变业务含义时由用户确认，不把局部示例、模型建议或旧成功记录当新规则。
