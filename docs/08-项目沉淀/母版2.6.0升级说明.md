# 母版 2.6.0 升级说明

日期：2026-09-07。母版保持未初始化，不包含具体客户数据。

## 变更与兼容性

新增三档执行深度、轻量执行简表、确认复用和风险升级规则。六问不取消，局部低风险问题可简写；验证按影响裁剪且不削减冻结基线。标准档沿用分文档结构；严格档增加风险评审、独立复核和恢复证据。

PROJECT.yaml schema_version 从2升级为3，新增 execution 和四项治理标志。初始化新增可选 ExecutionProfile，默认待确认。门禁登记使用 JSON schema_version=1；开发证据只接受已确认/已交付，发布不再接受待确认。

## 旧项目升级与回退

禁止将母版整体覆盖旧项目。先保存旧项目版本和未提交改动，再逐项比较 AGENTS、清单、脚本及受影响文档；新增字段保持待确认/false。旧 true 值不能自动转为证据确认，必须追溯原始授权。迁移索引时先确定唯一源，合并维护不能覆盖已有实质内容。原脚本与新清单应成套升级，不支持旧 schema 自动转换。

母版本次修改前快照位于 docs/.staging/v2.6.0-validation/before/，仅用于核对与回退，不是维护源。回退时逐文件比较并恢复原版本，保留新增文件，不自动删除目录或文件。旧项目按自身版本控制回退，不使用母版快照覆盖业务内容。

## 六问与验证计划

- 问题类别：执行深度没有明确分级，门禁登记不能充分约束状态一致性。
- 不变量：工作量随风险变化，但真实确认和验收边界不能被状态字段替代。
- 共同机制：统一清单缺少档位与证据契约，检查器接受草稿/待确认。
- 公共责任层：执行规范、项目清单、初始化和统一门禁检查器。
- 通用规则：上下文分级、统一证据记录、失败关闭；检查只证明登记一致性。
- 回归矩阵：三档正常路径、未初始化、缺失证据、非法档位、风险冲突、草稿、重复/越界证据、发布缺少授权/严格复核，以及适用专项。

测试使用隔离的合成项目和明确标注的测试确认记录，不作为真实业务确认或产品验收。最终验证结果见下文；原失败输入与日志保留。

## 回归期间失败记录

首轮测试脚本在重复门禁案例构造处报告 IndexOutOfRangeException（Test-TemplateRegression.ps1，第88行）。原始合成输入与前序日志保留在 validation/run-* 目录。六问：类别为测试夹具换行兼容；不变量为 CRLF/LF 均能枚举全部治理项；共同机制为行尾正则没有接受回车；责任层为测试夹具读取；通用修正为接受行尾空白并对空集合立即报错；回归覆盖 Windows PowerShell 5.1 和 PowerShell 7，保留原失败副本。不修改业务预期和冻结输入。

第二轮正常路径被拒绝，日志指出未知 gate is_template：测试枚举误读了其他 YAML 分区。类别为同名类型字段的作用域混淆；不变量为只从 governance 枚举门禁；机制为全文件布尔值扫描；责任层为夹具解析；修正为限定分区后枚举；验证保留跨分区反例并重新运行全部正反路径。检查器正确拒绝未知门禁，不放宽检查。另核对并恢复历史 2.5.0 变更条目的原版本号。

发布正例遇到 Git 未跟踪 .env.example，被检查器正确阻止。六问：类别为夹具隔离规则优先级；不变量为登记专用正例不含待提交变更；机制为 .gitignore 的否定规则覆盖 info/exclude；责任层为合成仓库设置；调整为只在合成副本末尾登记忽略，并增加显式脏工作区反例；矩阵继续验证发布拒绝。此正例仅验证登记判断，不证明真实 Git 提交或发布制品基线存在。未在母版或业务仓库提交。
