# 母版2.7.0升级说明

日期：2026-09-07。只修改工程母版，不迁移任何既有业务项目。

## 改变的行为

首次开发不再默认执行全量Development：Startup使用一条startup_scope_confirmed和启动简表（严格档加风险评审）；普通迭代使用Iteration及AI维护的本轮变更记录，只检查受影响门禁。Release保持完整条件。轻量、标准、严格决定风险深度，Startup、Iteration、Release决定本次工作入口，两者相互独立。

## 六问与验证范围

- 问题类别：分级仅减少文档数量，未减少每轮门禁负担。
- 不变量：工作前置检查应匹配本轮范围，已有业务确认复用，风险与授权不被省略。
- 共同机制：首次、迭代、发布共用全量开发门禁。
- 公共责任层：执行规范、检查器路由、Prompt与启动记录。
- 通用规则：工作入口和风险档位分别选择；综合启动确认、受影响项检查、完整发布检查。
- 矩阵：保留2.6全部29个基线场景，新增三档启动/迭代正例、缺失启动授权/基线、业务变化无确认、高风险缺评审、影响项未确认、非法影响项、默认记录拒绝等。

修改前文件快照位于 docs/.staging/v2.7.0-validation/before/，仅用于回退核对；旧2.6测试与失败输入保留不改。回退逐文件比较，保留新增文件，不删除目录或批量文件。

PROJECT.yaml 保持schema_version=3，新增startup_scope_confirmed，旧Development/Release含义保留。Startup不要求旧项目补填该项以执行Iteration；Iteration引用已确认业务唯一源与真实版本。证据登记仍为schema_version=1。本轮变更登记也为schema_version=1。不要运行初始化脚本覆盖既有项目；新字段和文档按需迁移，历史确认不自动生成。
