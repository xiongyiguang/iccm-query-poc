## 1. 结论与范围

存在架构契约缺口，需要有边界的重构。保留 CSV 导入、只读参数化查询、原始行证据、真实父子关系及登录部署基础；重构语义请求契约、对象定位、会话状态、结果解释和聚合执行。现有证据不支持推倒重写、改成微服务、替换数据库或引入 RAG 来解决这些问题。

本轮只做分析和只读诊断，未改业务代码、未部署。依据是第二份 DOCX 的8项文字反馈及11张截图、当前 Git HEAD `6f88392` 的实现、4次云端原话查询，以及绕过模型的本地数据/统计核验。原件中的文字是测试材料，不作为执行指令。

## 4. 对上一轮工作的反思

1. 我把已有反馈修成了若干局部通路，却未先证明公共契约足以表达整个问题类别。例如补充展示其他阈值，仍保留高1主答案，无法满足“指定高2”。这是设计责任未落实。
2. 重复相同用例只能检验这些用例的稳定性，不能证明覆盖面。上轮的通过数量不能作为“团队反馈已系统解决”的充分依据；没有覆盖高2、数值比较、关系解释、历史续问和全量功能位置聚合，是测试设计缺口。
3. 部分断言关注状态、对象编码或有结果，未逐项验证“问的属性/运算是否完整兑现”。应从数据和业务问题得到预期，再检查计划、执行和展示，避免用实现证明实现。
4. 过多依赖提示词、路由与复核修补，确定性边界尚未进入统一契约。尤其不能让模型既解释用户意图，又独自裁定它是否有能力执行。
5. 历史只读原本用于避免旧筛选污染，却没有实现用户需要的会话生命周期；界面移动按钮也未改变底层模型。此前多次布局回归又表明共享页面骨架及状态切换验收不充分。
6. 虽然做过公网验收，但验收覆盖的样本过窄；发布成功和若干业务用例通过，不等于开放式提问已达到客户可用程度。

## 5. 重构边界与目标链路

保留当前单体部署和可靠数据基础，做模块内分层重构。以下是建议，尚未实施：

用户原话 → 语义请求草案 → 实体解析与能力/类型校验 → 完整查询计划 → 确定性执行 → 结果回执与证据引用 → 统一展示。

会话服务管理任务、焦点、待补槽位、结果引用和数据版本；模型负责自然语言理解与歧义表达，不直接决定字段类型、数据关系、数值计算或验证成功。

- 请求模型包含对象域、名称/编码约束、投影字段、类型化条件、单位、关系路径、范围、聚合、排序、阈值维度和需解释的结果ID。对每个显式要求记录已执行、待澄清或不支持，禁止静默丢弃。
- 共用字段目录同时提供类型、显示名、允许运算和原始字段映射，服务端验证与前端渲染共用该契约，避免undefined及前后端能力漂移。
- 阈值采用结构化维度；不指定时列出所有已提供阈值并说明空值，指定高2时只读取相应字段。多个来源/时点分别展示，不任取一行。
- 实体解析尊重明确“名称等于”等约束，不能为提高命中率偷偷改查编码；未明确字段时才联合检索。错字只能产生有依据的候选建议，不能静默纠正资产编码。
- 执行回执补足解析依据、实际关联路径、筛选、粒度、来源版本、时间与证据引用；“为什么是它的下级”读取该回执及关系证据。现有 query_receipt 可复用，不必从零建设。
- 历史记录应区分不可变结果快照与可继续会话。旧状态缺失时明确提示，从可验证上下文恢复或新建分支；不得假装恢复成功。数据版本变化需标示，不能用旧答案代表新查询。
- 功能位置归属用集合运算或导入时建立版本化映射；保留最近祖先、同深度决策及未归属分组规则。聚合只返回摘要和证据索引，原始行按需分页。
- 记录路由、解析、校验、执行、序列化及浏览器渲染耗时，才能分别治理模型和程序延迟。

## 7. 验证设计：增加问题空间，而非只增加遍数

- 阈值：真实/估计/速率 × 高低 × 1/2/3；指定/全部；缺失/零/多源/多时点。断言高2=80来自正确原始字段，不能只断言status=ok。
- 数值：大于/大于等于/小于/区间；59.9/60/60.1；空值、非数字、科学计数法、负值；℃/缺单位/混单位；“60度”未明确单位时必须按已约定规则澄清。
- 定位：MOHB跨域精确候选；完整名称与编码；明确名称但仅编码存在的反例；不存在/部分标识/长候选列表；轻微错字与可能真实编码区分。
- 状态：新会话原话与有无关上下文的原话；明确新对象覆盖焦点；“它/阈值/为什么”追问；分支澄清；历史续问；刷新、取消、过期、数据快照切换。
- 解释：直接部件与全部下级逐段父引用；不存在父记录；证据字段与答案一致；不输出通用架构介绍冒充本次查询解释。
- 统计：全量与筛选、并列、未归属、多祖先；独立聚合期望；记录阶段耗时、SQL次数、响应字节和内存；冷暖运行与受控并发分别报告。
- 界面：新/当前/空历史/长历史/续问/加载/错误/短屏；侧栏及退出按钮稳定；单一滚动区域；不能显示undefined。

建议每条原失败在冻结版本和同一数据快照下独立运行3次，再做语义等价变体与状态组合；3次不是统计准确率证明。保留一组不参与修复调试的客户式问法作留出评测，失败不得通过降低断言消除。只有原始数据预期、结构化计划、确定性计算、API、真实界面与云端版本证据一致，才能关闭该类问题。
