## 编码前六问

|问题|结论|
|---|---|
|问题类别|跨语义协议、执行、上下文与回答的属性需求丢失|
|不变量|已定位对象不等于完成回答；每项所问属性必须得到有证据的结果或明确的数据不足说明|
|共同机制|object 被压缩为对象名称，固定展示模板丢失所问属性；后续状态不保留回答目标|
|最低公共责任层|意图契约及共享属性投影层，连接语义解释、数据证据和答案覆盖检查|
|通用规则|对唯一定位的主体，按显式请求的属性逐项取证；多主体消歧，不擅自选首项；缺失、不可判断和多来源分别表达；追问继承主体但重新解析回答目标|
|验证矩阵|原失败双问、名称/编码/类型/父级、不同对象树、多属性、零结果、多候选、缺值、跨源冲突、纠正/切换话题、批次、非法字段及历史查询|

## 原失败与预期

用户问题1：这个 PBS对象名称：XXXX2834 是什么类型的对象。
问题2：什么类型的。
两次截图答案均为“测点名称：测量点名称5……PBS对象名称：XXXX2834”，并显示读数表，没有回答类型。
原始 PBS 记录类型为时序测点。预期先直接回答类型；第二问保持该对象并回答类型；问物理量时不把对象层级或编码推断当答案。

## 实现设计与复用

复用 Store 的参数化筛选、对象索引、证据定位和已有关系/计算能力；不引入查询框架或自由 SQL。新增 attributes 操作与 properties 列表，属性目录同时供应模型说明和执行映射。定位与输出独立；属性结果保存 requested_properties、属性状态、来源字段和 coverage。验证器拒绝未知属性和跨操作丢失。自然语言含义由模型结合上下文决定，不新增问句关键词分类。

原 object 及引导操作兼容保留；新自然语言属性问题走通用投影。物理量含义暂不从代码、名称或单位猜测。统计、关系、阈值仍使用现有执行器，复杂多问题使用既有 batch。

上下文保留请求属性与已回答属性；明确续问补足主体，纠正时以本轮属性为准；数据不足的成功定位也可继续追问。页面按属性结果呈现，不再附带无关读数表。证据与原值一一对应；覆盖检查只能证明请求计划得到执行，不能证明模型永远正确理解自然语言，真实模型矩阵另行验证。
