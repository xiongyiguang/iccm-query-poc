# 独立条件清单与模型对照

版本：V1｜2026-09-24｜本地候选与真实模型实验；非客户验收、非腾讯云发布。

## 结论

本轮已把“看着候选查询给通过/不通过”的复核，扩展为独立提取完整条件清单，再由程序比较两份业务请求。清单提取不接收候选计划；源文片段由程序编号，模型引用编号，程序还原原文。条件相同直接通过；不同时只允许选择一份完整、已校验请求或澄清，不允许拼接出第三份查询。

这解决了上一阶段验证器依赖候选、只能判断局部正确的问题，但两次提取加一次裁决仍不是正确性证明。完整试验发现复核模型也会误解业务词典，且普通查询偶尔仍进入旧路径。因此新机制保留为显式试验开关，不以局部通过替换全部验收。没有为失败问句增加正则或问法分支，没有训练模型或引入RAG。

## 六问分析与实际改动

|问题及原始反例|系统性原因|本轮公共机制|剩余边界|
|---|---|---|---|
|单位非空条件被漏提取且覆盖复核未发现|复核以候选为中心，容易确认已有答案|独立读取原话、确认状态，逐条给出完整条件；程序对账|两份提取可能同错|
|V2提取了正确属性，却同时写search；结构修复删掉属性|同一事实同时由operation与properties两字段决定|清单协议V3仅用properties，程序派生查询形式|首次返回字段仍须语义判断|
|A14把config说成不是构型树，选错跨树范围|系统只提供英文枚举，没有共享业务定义|目标树、层级、属性来源及含义统一进入业务目录|目录内容仍需业务维护|
|A19复核认为resolved_identity是虚构条件|把程序内部等价比较键当成模型理解材料|内部键只用于程序比较；裁决读取带原话依据的原始请求|实体等价仅证明当前数据对应，不证明语言语义等价|
|H05把完整名称截成尾号；M10从旧路径复发|脱敏名称形态易误导模型，入口未完全统一|从原话与导入数据逐字提取完整名称/编码引用，独立提供给新提取器|旧兼容路径仍可能绕过该机制|
|J02缺legacy封装字段直接报错|结构修复只覆盖内部槽位，遗漏外层协议|外层封装纳入已有的一次结构修复，不放宽协议|修复仍可能失败，失败不执行|
|K04将“未报警”改成not_contains“报警”，返回10464条而非1921条|裁决缺少状态实际取值和文本比较语义|提供原始类别值、空值含义、比较方式和列表/属性返回规则|裁决仍是概率模型|
|页面A01明确摄氏度却被独立模型判歧义|把模型的“不确定”直接当成程序校验错误|区分结构错误与语义分歧；后者可受限裁决，选择草稿只能澄清、不能执行|主提取直接进入歧义及两份共同错误仍需持续测量|

明确单位过滤是单位状态的事实来源；模糊“度”的数值条件保存为待澄清草稿，不生成不可能匹配的单位过滤。失败和待澄清草稿均不替代最后成功执行的请求。单元测试分别验证结构修复次数、提取隔离、完整名称、跨树/重复行身份、字段投影、草稿与执行隔离、不能返回第三份计划。

## 真实模型对照

调用为现有DeepSeek官方接口，不是模拟输出；实际响应记录Flash为deepseek-flash、Pro为deepseek-v4-pro。只发送既有授权范围内的脱敏问句、必要上下文、业务目录及少量逐字引用；没有发送Word原件、整份CSV或密钥。仅保留usage、模型标识及结构化结果，不保存模型思考正文。

同一份24题，每题两轮。题库含10题回归及14题首次封存的新单句；实验提供事先正确的prior，不能当成完整多轮对话表现。后续版本继续使用同一题库，属于回归而非再次盲测。

## 运行开关、回退及发布边界

新机制仅当ICCM_COVERAGE_ENGINE=checklist启用。最终测试设置ICCM_CHECKLIST_MODEL=deepseek-v4-pro、ICCM_CHECKLIST_THINKING=disabled、ICCM_CHECKLIST_EFFORT=low；主模型仍Flash。默认不设置该开关时仍走原request-coverage复核；不要误以为仅复制代码即已启用新流程。

程序复用现有字段目录、参数化执行器和签名会话。关系、统计等未整体迁移；普通查询偶发走兼容路径是未关闭的迁移缺口。退回review配置只恢复上一试验路径，不代表该路径已解决全部语义问题。代码、提示词及运行设置需成组部署；本轮没有提交GitHub或部署腾讯云，未重新核查云端当前版本，沿用此前r8登记。

## 下一阶段验收重点

1. 统一已迁移查询的进入路径：无论模型选择何种封装，普通列表和属性查询都不能绕过同一语义核验与状态提交边界。关系、统计仍按各自契约逐类迁移；不靠扩充问句分支路由。
2. 缩小概率裁决的权力：业务目录维护目标、状态枚举、属性组、空值和操作符含义；对真实分歧展示具体条件差异，无法判断时澄清。来源片段不是语义正确性的证明。
3. 单列误答、误澄清、未完成和慢响应率。新题封存后多轮运行，不挑选最好的一次；最后修正仍须完整发布回归与腾讯云实测。
4. 引入业务人员提供、开发时未见的新问题及顺序，预先确定正确口径。当前同一助手设计的留出题只能证明局部泛化，不能代替客户盲测。

本轮不宣称开放问法全部解决。完整失败记录是发布门禁证据；不能为了通过把状态未知归为未报警、把列表改为详情、丢掉单位或允许旧路径偷偷跳过核验。
