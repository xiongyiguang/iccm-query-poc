## 结论与事实边界

六类反馈并非六个独立文案问题。当前系统把语义规划、安全执行、会话状态和产品呈现之间的责任边界切得过窄：澄清没有成为可续接任务；语义路由看不到上一轮问题；对象定位提前锁定名称或编码；统计字段目录未覆盖对象层级；原始值忠实保存却缺少可读展示；会话计算缓存被当作历史对话能力。

以上机制由代码确认。截图缺少模型原始输出、请求日志和当时数据版本，因此不能断言每条现场问题经过哪一条模型分支，也不能把本地回归当作云端问题关闭。现场截图的 1970 时间、单位缺失只证明来源值异常或缺失，不证明系统应自动纠正。当前导入器支持 CSV，截图称“excel”不足以证明原始 XLSX 已被直接导入。

## 分阶段实施计划

1. P0 冻结五张截图、代码基线和原提问，按系统性等级分析。只读检查原字段与机制，先形成六问。
2. P1 会话与能力契约：澄清任务入状态、语义路由携带历史；共享分组目录；版本化新Prompt与schema，保留V21。验收以连续原问、独立问题不污染、分组守恒为准。
3. P1 定位与表达：联合标识规划、公共详情候选召回、精确数值展示。候选不自动执行；原值与证据不变。验收包含误匹配反例及各详情操作。
4. P2 历史可查：复用浏览器原生标签页存储和现有界面组件，支持当前标签页刷新及新对话后的查看；明确关闭标签页、退出后不再保留，不宣称跨设备永久历史。账号级长期持久化需要另行设计身份归属、保留期限、容量、迁移与权限测试。
5. 验证：冻结失败样本、合成边界、现有全量自动回归、真实模型多轮、实际浏览器操作分别留证。云端发布另按Release执行，不由本地通过推导上线成功。

## 复用与兼容设计

复用现有SQLite参数化查询、Store.filtered、query_plan业务反馈、属性目录、浏览器原生sessionStorage和现有dialog组件，不增加第三方运行依赖。不引入向量库或编辑距离自动选点：本轮证据首先要求编码片段候选和字段中性定位，不能据此扩张到任意错别字自动纠正。

原始CSV、导入快照、旧Prompt与既有测试均保留。新增输出字段保持旧value兼容，原始证据核验继续以value为准。历史查看不重新查询、不自动恢复旧筛选或把旧快照结果视为当前。快照切换仍使查询状态失效。

### 失败反证与机制修正

全量回归还发现旧流程要求澄清期间保留已有query，已修正为“续接澄清保留有效范围，明确独立新问题清除旧范围”，不通过弱化原测试解决。

## 对话切换引起整页跳动修复 2026-09-23

用户两张截图显示侧栏整体随历史切换移动。原布局下实际复现：1536×900，10个历史会话，window.scrollY=13；切换前侧栏top=76、新对话top=137.4375，切换后分别63和124.4375。根因是整页滚动与受父容器底边约束的sticky侧栏共同作用；不同视图高度切换使父容器边界推移侧栏，并非按钮选中颜色的问题。

不变量：切换内容不能改变顶部导航、侧栏按钮或主区横向位置；返回当前对话应恢复原阅读位置。修复将应用外壳约束在视口内，主内容独立滚动；侧栏自身滚动隔离，历史列表可收缩并局部滚动；预留滚动条宽度并关闭主区滚动锚定。历史从顶部展示，返回恢复当前对话的scrollTop，新对话清零。未修改业务查询及历史保存范围。

真实Edge验证10个历史会话、1536×900/1440×720/950×850/560×780四种视口、12次往返切换：按钮坐标及主区宽度不变，window.scrollY始终0，当前对话滚动位置恢复误差小于1px，新对话归零，无页面脚本错误；现有前端运行检查通过。检查截图docs/.staging/team-test-20260923/stable-history-layout.png。当前为本地验证，未发布云端。
