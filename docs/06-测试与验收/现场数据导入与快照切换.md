# 现场数据导入与快照切换

V1｜2026-09-20｜已实现，完成限定范围验证

## 设计边界与六问

|项目|决定|
|---|---|
|类别|新增共享数据生命周期，影响查询、证据、上下文和持久化|
|不变量|失败不改变活动数据；所有查询使用一致快照；证据保留上传文件名与行号；替换不删除原文件|
|现有机制|启动直接读五CSV、只读内存SQLite，点记录内部行号等同源行号，前端数量固定|
|责任层|数据导入解析/完整候选构建/原子活动版本切换，HTTP版本及会话隔离|
|通用规则|预览校验后提交；追加对象同码同值跳过、同码异值拒绝；测点保留不同记录，同内容文件重复上传跳过；替换只使用本批文件，未提供类为空；旧版本保留可恢复|
|矩阵|CSV编码/字段顺序/空表/坏列/对象冲突/重复文件/多源同码/循环/缺父引用/追加替换/失败回滚/重启恢复/旧预览失效/忙会话/页面联动|

当前按五种既有数据结构CSV实现，字段不同的新表不自动获得问数能力；本版不支持Excel和不同字段新表，后续按实际样表扩展。沿用白蓝界面、对话框、既有字体和表格；入口在顶栏，默认追加，替换说明整库范围，先预览再提交。未知文件路径不能作为服务端读取或写入路径。无新增第三方依赖。原数据只读；快照使用系统生成名称保存到inputs/imports，不删除任何目录或批量文件。


## 使用方法

顶栏“导入数据”→选择追加或清空→选择1—10个CSV→为每个文件选择五类中的实际类型→“校验并预览”→核对五类前后数量、缺失引用提示→确认导入。可以只选一类；字段名称必须完整一致，列顺序可不同，不自动猜测不同字段的含义。单文件16MB，总上传32MB；当前快照最多30万源记录、结构最多64层。

追加时对象按树+编码核对，同码同内容跳过，同码不同字段值整批拒绝；测点不按编码去重，保留多源/多条记录，相同类型且字节内容完全一致的文件重复上传跳过。行号指CSV记录行序；上传来源带文件名和内容摘要，防止同名文件证据混淆。阈值直接使用该记录的原始证据字段，避免多文件行号碰撞。

清空范围是全部五类活动数据；没有在本批提供的类型变为0。校验和候选构建失败不切换，提交时先保留旧快照和新快照，再原子切换active.json；临时文件写完才成为可恢复快照，写盘失败不发布。重启按active.json恢复，不静默退回原CSV。恢复历史也先预览再提交，不删除源文件或历史文件。

查询忙时拒绝提交；提交与新查询使用同一锁，切换后清除全部旧会话/结果。网页提交版本号，旧标签页会提示刷新。当前页面同步计数、清除旧对象缓存、重置对话；原示例对象不存在时隐藏对应推荐入口。

## 限制与恢复

只支持既有五类结构CSV，不自动支持Excel、任意字段或其他业务表。此功能不建立新字段语义映射，不改变既有跨树编码规则；其他行业/编码体系需另行建模。快照为本机文件，未新增数据库服务和第三方依赖，未调用模型处理导入。现场新数据是否脱敏不能由系统断言；数据提供方负责确认。

完整快照会占用磁盘，历史不自动清理；本轮未做批量删除。回退代码参照`.staging/import-20260920/before`；需要恢复数据时优先使用历史快照功能，不手动清空目录。阶段工程登记原有“基线未正式确认”缺口仍保留，不将本次功能测试当正式发布验收。
