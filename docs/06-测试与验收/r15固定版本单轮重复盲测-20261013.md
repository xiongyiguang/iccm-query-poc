## 集中修复设计与边界

本轮属于共享关系变更接入的系统性问题，保留首次4次HTTP422及全部三轮原回执。共同规则为原表输入、返回对象域及联合筛选各自独立。实际数量仍由原Graph计算，未增加Prompt、依赖、SQL、数据别名或业务编码专用分支。

1. 问题类别：合法输入被跨树身份/分类槽位拒绝，模型遗漏联合型号条件；不是数据计数错误。
2. 不变量：原话明确字典起点不能被构型目标字段改换；现场位置与精确型号条件同时保留；未知、歧义及冲突不能变成零或宽范围。
3. 共同原因：原配置型号引用没有进入可证明等价的选择接口；遗漏条件只会拦截，未使用已明确输入建立受限绑定。
4. 公共责任层：关系变更接入和严格编译层，沿用Graph实际身份与父引用核验。
5. 通用修复：仅实际同码分类对应、原话明确字典源且构型目标时恢复字典起点；实际config型号可经同码同父、角色equipment_config校验进入既有精确型号筛选。当前独立PBS集合原话明确采用关系且唯一型号时，程序补回有来源的精确选择，保持根、深度、其他条件；多个型号、比较、排除、未采用、缺字典、父引用冲突均不猜。
6. 验证矩阵：输入代码/名称、字典源/构型目标、位置与型号交集、真实零、同码冲突/缺失/分类冒充型号、多个型号、否定、错误型号、直属与其他分类保留。新增12项合成业务测试不含客户专用分支；原4次真实失败提取离线回放4/4。修复后原12题三轮云端实测另行判分。
