# 需求清单与验收草案

版本：V1｜整理日期：2026-10-08｜用途：当前工程交接；非客户正式验收。

沿用历史详细设计的R01至R07需求编号，避免重建另一套需求标识。客户题集、复杂度分组和正式签字尚未确认。

|需求|业务要求|实现/证据入口|验收草案与现状|
|---|---|---|---|
|R01|四树对象名称、分类、上下级及部件关系|data、relation_check、related_parts|按原字段、父链及字典逐项核对；有限样本通过|
|R02|测点、报警、值、单位、阈值及时间|attributes、query_filters、typed_fields|记录数和编码数分开，缺值不补0；自由字段表达仍有反例|
|R03|多轮上下文、补答、换题与切域|business_request、request_gateway、app|逐轮与整段都完成原任务；第三轮仍开放|
|R04|直观结果、业务口径、分页、依据和对象操作|frontend、query_presentation|业务交互与实际结果一致；第三轮快捷操作需核对|
|R05|简单≥90%、复杂≥70%|模型与评测设计、验收记录|目标未改变；有限回放不等于总体准确率|
|R06|提交到完整结果≤5秒|server_ms、浏览器计时|普通版云端存在超过5秒；Agent完整结果约10–13秒基线|
|R07|报警时长问答|data中的duration边界|缺少开始/恢复时间应说明不能算，不能用测量时间代替|

场景成功需同时满足对象、条件、范围、输出动作、完整集合及依据。若任务可完成却反复澄清、只列记录不做所问排名、模型失败却返回0，都不能算正确。真正缺数据或能力不支持须清楚说明，并单独统计，避免拉高可回答题准确率。

正式验收建议冻结代码、Prompt、供应方响应模型、参数、CSV哈希和题集。保留全部失败样本，分别记录业务正确性、时延、执行路径及浏览器呈现；最终阈值执行方式和责任人仍待业务确定。
