## 当前架构与职责

浏览器原生HTML/CSS/JavaScript → 本机HTTP接口 → 两阶段DeepSeek语义规划 → 契约校验 → 内存SQLite查询/确定性统计 → 表格、图表和原始证据。

backend/model.py读取context-scope-v2.txt判断上下文需求及标识字段，再读取query-intent-v10.txt生成V6 schema限定的意图；不生成任意SQL。backend/query_filters.py校验字段与操作，data.py执行关系/详情查询，analytics.py计算分组和记录占比，query_plan.py执行2至4项独立任务。frontend/app.js呈现结果及会话对象。

### 五层逻辑架构

这里的“五层”按职责划分，不是五个独立服务或五套系统。同一代码模块可能承担多个层次的工作；当前仍是本机 DEMO，不代表已建成生产级分布式架构。

| 层次 | 职责 | 输入与输出 | 当前实现对应 |
|---|---|---|---|
| 1. 交互展示层 | 接收自然语言、对象选择；展示回答、图表、明细和依据 | 问题/点击 → 请求；结果 → 页面 | `frontend/app.js` 及页面样式 |
| 2. 会话与任务编排层 | 管理当前对象和筛选、组织连续问答、执行多问题分支 | 问题＋会话状态 → 带上下文的任务；结果 → 更新后的状态 | `backend/app.py`、`backend/query_plan.py`，与前端会话交互配合 |
| 3. 语义解析层 | 理解意图、指代、对象类别、范围、字段和匹配方式 | 自然语言＋必要上下文 → 受约束的结构化查询意图 | `backend/model.py`、上下文及查询意图 Prompt、意图 schema |
| 4. 查询与计算层 | 校验计划，执行关系查询、全部条件筛选、分组、排名和占比 | 合法查询意图 → 真实结果、计算指标和执行状态 | `backend/query_filters.py`、`backend/data.py`、`backend/analytics.py` |
| 5. 数据与证据层 | 加载五份 CSV，提供对象关系及原始来源，保留空值与重复记录 | 原始文件 → 可查询数据、关系、文件名和行号 | CSV、内存 SQLite、数据加载与证据组织逻辑 |

请求从页面进入会话编排，语义解析给出计划，程序校验后查询数据并计算；结果和证据再经编排返回页面。数据层同时为执行提供依据，并非每次请求都重新导入 CSV。

### 语义解析具体做什么

当前自然语言路径使用两阶段 DeepSeek 规划：先判断是否需要历史上下文、标识涉及名称还是编码等字段，再结合必要上下文生成限定结构的查询意图。明确的引导操作可提交意图，不要求每次按钮点击都重新解析自然语言。

语义判断包含：

- **对象与类别**：问的是 PBS 现场对象、构型、分类字典还是测点记录。
- **指代与范围**：“它”承接哪个已确定对象，“这些”承接哪个集合；直接下级与全部下级分别处理。
- **任务**：查名称、关系、测量值与阈值，还是筛选、分组、排名、占比。
- **条件**：名称或编码、精确或包含，以及报警、开关等附加条件；显式限定不可静默丢弃。
- **澄清**：多组答案后的“它”无法唯一确定时说明缺口，不擅自选择第一项。

模型负责结合上下文理解含义，不能靠穷举问句或追加关键词替代语义分析。程序负责结构和字段校验、精确查找、计算与证据一致性；模型不直接编造数量，也不生成任意 SQL。结构合法不等于语义一定正确，因此仍需同义问法、范围切换和连续追问的真实回归。

### 一条问题如何经过五层

前提：当前对象已唯一确定为构型 MOHB01。用户问：“它的全部下级部件按部件类统计，各有多少个？”

1. 交互展示层提交问题和当前会话信息。
2. 会话与任务编排层提供当前对象；不会把上一轮列表第一项擅自当成“它”。
3. 语义解析层将“它”解析为 MOHB01，范围为全部下级，目标为部件，任务为按部件类计数。
4. 查询与计算层沿实际父子关系查部件，关联所属部件类，对完整集合计数，不只统计当前页。
5. 数据与证据层提供原始记录及来源。当前快照对应 221 条部件、27 个分组；结果返回展示层呈现图表和明细。

这些数量来自当前数据和程序计算，不是写在语义规则中的固定答案。接着问“改为前3组”，应保留对象、范围和分组条件，只调整展示组数。

若问“平均报警时长”，执行层还要检查数据前提。本批缺少报警开始/恢复时间，应该返回数据不足，而不是由模型根据测量时间猜算；该失败不应清空已确定的对象和应保留的筛选。

### 为什么 DEMO 可以较快完成

本阶段只处理五份固定格式的脱敏数据，复用模型服务、数据库和浏览器展示能力，范围限定为只读查询和部分统计；没有包含生产数据同步、正式用户权限、设备写回、连续历史分析或 RAG 知识模块。因此可以较快形成演示闭环。

开发快不等于业务语义简单或已全面验收。对象与集合的区分、不同设备数量口径、跨树关联、条件保留和数据不足处理，都是已暴露过问题并需要持续回归的部分。五层职责有助于定位问题，不能作为质量已达标的证明。

## 数据、对象与状态

五份CSV来自上一级脱敏数据目录；启动加载，保留来源行和字段。PBS/构型/设备类/部件类是不同树，监测记录按测点编码关联；实际父子字段优先于字符串猜层级。明确完整标识的详情使用equals/entity；包含集合使用contains，identity表示名称或编码。名称和编码字段显式限定不应混用。

entity保存当前对象，query保存集合筛选，lookup_query保存详情记录条件，三者不能相互覆盖。成功唯一定位可更新对象；错误、澄清、寒暄及数据不足不覆盖成功上下文。批次分支需单独选择，不猜第一项。每会话单条在途请求，取消使迟到结果失效；状态和结果只存内存。

## 能力与计算边界

支持对象名称、上级、类关系、直接/全部下级部件、监测及原始阈值、受支持分组计数/排名和测点记录占比。按query执行全部条件，唯一编码多个来源仍逐条保留。阈值差值使用实际数值；空值不补零；18项阈值原样可查。任意数值聚合、连续趋势、预测及故障诊断不在已实现范围。

V10.2时长请求先校验查询合法性，再判断数据前提；本批数据没有报警开始/恢复时间，直接data_insufficient，无候选列表或虚构指标。数据不足不会通过选择对象解决。

## 2. 页面与交互

页面标题“iCCM智能问数”，页头显示“脱敏数据·导入快照”。统一输入框和连续对话，不分设备/监测两个业务入口。对象浏览和证据按需打开，默认不占据固定三栏。

```text
┌ iCCM智能问数    脱敏数据·导入快照    [浏览对象] [新对话] ┐
│ 用户：这个PBS对象对应什么设备？                         │
│ 回答：设备描述＋编码     [关联路径] [查看依据]           │
│ PBS对象 → 设备构型 → 设备类                             │
│                                                        │
│ 用户：它下面有哪些部件？                                │
│ 回答：直接部件51个    [直接下级] [全部下级]              │
│ 部件名称                 编码             所属类别      │
│ ……                       ……              ……            │
│ 当前对象：MOHB01   范围：直接部件   [清除条件]            │
│ [ 输入问题；可粘贴编码或搜索名称                  ][发送]│
└────────────────────────────────────────────────────────┘
```

空白页三张推荐问题卡：对象对应设备、下级部件、开启且报警的测点。前两项可选对象再提交。名称优先、完整编码并列；同名显示对象类型区分，不替换脱敏名称。对象浏览可切换四棵树，作为导航，不分割问答；树按需展开，不能一次渲染几万个节点。

结果形式：名称结论卡、局部关系路径、数量与口径、分页明细表、阈值对照。表格默认20行，显示总数，按编码/来源稳定排序；分页不改变统计范围。点击一行选择对象，下一问使用该对象；不自动发起模型调用。

右侧抽屉分“对象详情”“数据依据”：源文件、行号、关联步骤、筛选范围、计算式。SQL与模型日志仅调试可见。新对话清空上下文，旧消息留在原会话，跨会话不隐式继承条件。

视觉采用蓝灰浅底、白色内容、清晰边界，红色必须配“已报警”文字。中文正文16px，辅助不低于14px；参考1366×768、1920×1080，125%缩放验证；窄屏详情用抽屉。键盘提交、清晰焦点和表头可访问。避免三重滚动。

状态覆盖：空白、处理中、成功、无匹配、数据不足、需澄清、错误、超时。处理中可取消；失败可重试，保留原输入。无匹配不同于0条报警或数据缺失。取消、过期响应不得更新上下文。

S04：“哪些开启监测且报警？”按开关开启且状态已报警查48条。显示名称、编码、关联功能位置、值、时间、状态及开关。未匹配PBS的16条报警仍展示，不能隐藏。

S06：“报警多久？”现有文件缺少报警起点、恢复时间和连续事件，回答“本批数据未提供报警开始时间，无法计算持续时长”，可列已有测量时间并注明不是报警起点。不能用当前时间减测量时间或返回0。未来有事件记录时才按开始/结束或有持续证据的截止时间计算，本期不虚构该能力。

## 5. 数据与确定性口径

原始CSV保存字段、字符串、文件哈希及行号；派生数值/时间字段另建，不改原件。测点记录键为文件版本+行号；测点编码用于去重而非覆盖记录。

|对象/指标|处理契约|
|---|---|
|PBS到构型|按&解析结构对象，精确校验构型及层级；测点沿PBS父链查结构对象，不盲目截断所有编码|
|构型到设备类|实际父对象连接设备类并校验类型，不把所有父节点当设备类|
|部件到部件类|所属部件类代码精确连接|
|测点到PBS|测量点编码=对象代码；未匹配保留原因|
|子孙数量|父代码递归、去环、去重、按层级筛选，不用代码前缀代替树关系|
|名称|对象描述与类别描述分别取源；缺失不猜|
|测点数/记录数|不同编码/原始行；跨源并列，不擅自择最新|
|报警|状态已报警；监测且报警另加开启；原因非空不等于已报警|
|数值|缺失不补0；Y等文本不做算术；不跨单位平均或猜单位|
|时间|1970标疑似占位，PBS分秒不补日期；不以测量时间算时长|

本机建立对象目录、各树祖先关系、经验证的跨树映射、测点来源视图。映射存规则版本和证据。数据更新必须重建派生视图并失效缓存和旧结果集合；历史消息保留原数据版本标记。

## 6. 多轮规则

会话保存current_entity、entity_type、scope、filters、result_set_id、data_version、last_successful_intent。完整结果集合在后端保留查询定义，不能只把当前页20行当“这些”。

|输入|状态变化|
|---|---|
|它下面/它叫什么|用最近明确对象；对象与类别皆可能时澄清|
|这些里多少报警|完整上一集合叠加条件|
|包括更下面的|修改层级，保留对象并重算|
|只看开启的|保留当前范围加条件，显示条件标签|
|换对象|替换实体，清除不兼容集合，是否保留筛选按语义判断并展示|
|独立新问题|清除不相关旧对象/条件|
|点选行|成为下一轮明确对象，不改历史答案|
|失败/取消|不更新成功状态，迟到结果按请求ID丢弃|

默认单会话一条在途请求，完成或取消后再提交，避免响应串线。澄清只更新待选信息，不假记查询成功。验收覆盖代词、集合、范围扩大、条件叠加、换题和重试。

## 7. 查询与AI边界

问题+上下文 → 模型生成结构化意图 → 契约和实体校验 → 参数化只读查询 → 计算结果 → 答案/明细/证据 → 浏览器完整呈现。

意图含operation（lookup/list/count/compare）、entity_type、entity_reference、relation_path、filters、aggregation、hierarchy_scope、context_action、clarification。字段和关系受允许集合约束；未知项不默认其他。模型不得任意执行SQL或文件工具。无效JSON至多一次受总时限约束的修复，失败明确提示。

模型负责开放语言和指代，确定性层负责关联、计数、计算和证据。普通结果直接组织回答，减少第二次润色调用。模型不写业务数据，不操作设备，不编造名称/数值。数据中的指令作为数据，不扩大权限。

接口草案：POST /query、GET /objects、GET /results/{id}、GET /evidence/{id}。响应含status、answer、columns、rows、total、context、evidence、data_version、timing。仅本机回环监听；配置密钥不入仓库和日志。

选型尚未冻结：优先评估本机SQL、成熟树表组件、可替换模型适配器。Codex runtime只是候选，尚未验证调用和耗时。实现前核对官方来源、固定版本、许可、维护与真实样本，不因知名或高Star直接采用。RAG、自治Agent和运行时文档抽取本期不适用。

## 8. 五秒设计

目标预算（未经实测）：准备0.2秒、模型3.2秒、验证与查询0.7秒、组织传输渲染0.6秒、余量0.3秒。预建索引与层级，不每问重载CSV。模型适配器可替换，先验证真实调用，不预设某模型达标。

计时从用户提交到答案、总数和首屏表格稳定可交互，包含等待、重试和渲染；首字不算完成。分页为显示安排，不以占位符结束计时；若客户要求全量行一次呈现，须按该口径测试。超过5秒记失败，即便稍后正确也保留性能失败。

冷启动、新会话、热会话、缓存命中分别记录；不得只用缓存证明性能。超时允许提示和手动重试，不用旧答案伪装新结果。

## 9. 验收与证据

客户阈值明确，题数和复杂度划分尚未明确。内部建议简单20题、复杂20题、边界8题，作为工程测试安排，不冒充客户确认。

简单：单表字段、筛选、计数。复杂：跨树、多表、递归、集合追问及组合；单表多轮另标上下文能力，不为分数换类别。V2的23题为种子，补充对象名称与类名区分、报警时长、多来源、空集合、换题、取消迟到响应。执行前冻结数据哈希、题集版本、预期值/集合和口径，不为过测改答案。

准确率=正确数/实际执行题数，失败不能剔除分母。名称须对象匹配，列表须无漏/多项，数字须口径精度一致，文字不同但事实一致可算正确。缺数据题单独评估，不混入可回答题提高准确率。超时但最终正确分别记录正确性和性能。

多轮逐轮及整段双报告。性能逐条耗时、最大值、中位数、P95、超5秒条数，均值不能替代单次要求。暂按单人串行，最终并发人数与澄清计时尚未约定，后续用具体测试案例集中核对。

浏览器验收覆盖统一入口、搜索、路径、表格分页、范围切换、证据、键盘、缩放、加载/空/失败/超时，以及上下文清除。脚本通过或静态原型不代表真实问数通过。

## 10. 顺序与当前限制

本轮仅设计。后续先模型调用和SQL小验证、可点击原型；再S01—S03真实闭环，扩展S04—S06，最后题集冻结与性能验收。模型或框架不满足目标时优化/替换，不能用固定答案冒充查询。

尚未验证：模型接入、依赖版本、实际耗时、页面运行。尚未约定：最终题集、复杂度分组、澄清计时、并发人数。不阻塞本轮设计，也不视为客户已接受我方默认值。

## V23 查询与会话契约重构（2026-09-23）
用户在第二轮架构诊断后授权实施。复用Python标准库、SQLite、原有单体服务及原始行证据，无新增第三方依赖。模型依旧只生成结构化意图，不能执行自由SQL。
- 数值字段采用Decimal比较gt/gte/lt/lte/eq_num；旧equals仅在值为有效数字时按数值相等兼容。缺失/非数字不补零。摄氏度、℃、°C作为同一单位表示；华氏度独立，不跨单位自动换算。“度”仍可澄清。
- 阈值18维字段目录共享给模型和执行器，thresholds显式投影；未指定时列全部。旧high1/difference数据字段保留兼容，主答案不再默认高1。
- 无明确树的详情用objects跨四树精确查找；同码不同树必须澄清，不由候选序号默认选择。显式名称/编码约束仍严格匹配。
- 独立语义路由记录阈值及数值条件，在执行前核对计划是否丢失这些要求。其语义抽取仍依赖模型，需留出评测，不宣称开放语言完全可靠。
- explain_result读取当前会话上一成功查询回执、父引用范围和来源行；多项或无有效结果须澄清。
- 功能位置分组批量读取真实祖先关系并选最近归属，分类分组批量读字典；不逐条查库。API首屏20条证据，/api/evidence分页查看，服务端按数据版本复用不可变原始行。
- 新对话不删除已完成会话；/api/resume用签名快照恢复对象、筛选及有限对话。保留当前标签页100轮，凭据有效8小时，服务重启或数据版本切换后旧记录只读。最多50个活跃缓存，淘汰空闲会话后可从有效签名快照恢复。不是账号级永久历史。
- 当前/恢复会话共用输入和渲染；旧版缺状态不伪装恢复。所有接口沿用登录、来源及CSRF检查；continuation不允许客户端修改后直接恢复。
