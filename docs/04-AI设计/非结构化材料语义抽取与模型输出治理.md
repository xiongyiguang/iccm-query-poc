# 非结构化材料语义抽取与模型输出治理

规范级别：semantic_extraction 或实际材料事实抽取能力启用时强制。异构材料集、模型输出变体集、独立留出集和特定事实证据追踪仅约束此能力，不自动推广至其他 Prompt/AI 功能；通用 Prompt 验证见 Prompt资产管理.md。实际引入能力须同步更新适用性及设计，不以状态尚未登记规避规则。

本规范适用于从合同、申请表、报告、证明、扫描件、邮件、自由文本、复杂表格及其他非结构化或半结构化材料中识别对象、字段、事实、关系、结论和证据的能力。目标不是适配若干已知模板，而是在材料字眼、版式、表格、段落、顺序和模型返回持续变化时，仍保持可解释、可降级、可评测和可演进。

## 1. 核心认识与不变量

自然语言和材料版式具有开放多样性。字段可能位于段落、表格、页眉、脚注、合并单元格、附件说明或跨页内容中；同一语义可能使用不同名称、句式、顺序、枚举和对象层级表达。已知样例、固定模板或正则集合不能代表真实问题空间。

系统必须始终满足以下不变量：

1. 不以固定行号、列号、页码、段落序号、文件名或已知模板坐标作为业务事实成立的依据；
2. 对需要语言理解的字段，以语义分析为主，不用关键词命中或“第一个匹配项”替代主体、关系、范围和上下文判断；
3. 每个有效事实都能追溯到原材料证据、解析版本、模型/Prompt/结构契约版本和标准化过程；
4. 模型输出必须经过统一接入层解析、映射、类型与枚举标准化、证据校验和跨字段一致性检查，不能直接写入业务表或规则引擎；
5. 不能识别、证据不足、明确空白、不可读、冲突和技术失败必须是不同状态，不得用空字符串、`false`、零或任意默认值混为一谈；
6. 快速路径失败、模型返回变体或单个字段失败不得无故阻断整个文件；系统应降级、隔离并保留可重试证据；
7. 新材料暴露的问题必须抽象为输入形态、语义关系、输出契约或证据门禁的问题类别，不得增加客户名称、样例字眼或文件专属分支。

## 2. 责任划分

|责任层|适合承担|不得承担|
|-|-|-|
|确定性解析|读取文件、保留段落/表格/页面/坐标、OCR、字符清洗、结构块切分|根据固定位置直接宣布复杂业务事实成立|
|确定性快速路径|识别有明确标签、表头、类型和边界的高精度候选；日期/金额等基础格式解析|以模糊关键词、首次命中或样例坐标绕过语义分析|
|大模型语义分析|理解主体、关系、否定、范围、指代、同义表达、跨段落语义和候选选择|替代权限、确定性计算、最终业务规则或无证据决策|
|统一输出接入层|容错解码、字段映射、类型/枚举归一、证据绑定、状态判定、版本记录|静默吞掉未知字段、自动补造缺失事实或把修复失败当成功|
|业务规则引擎|基于已验证的规范化事实执行可审计规则|直接读取模型自由文本并临时解释业务规则|
|人工处理|处理证据冲突、高风险不确定项、材料不可读和授权决策|常态化补偿本可通过系统机制解决的结构差异|

## 3. 推荐处理链路

统一链路为：

材料输入 → 原始结构保真解析 → 语义块与候选构建 → 模型语义抽取 → 宽容解码 → 规范字段映射 → 类型/枚举标准化 → 原文证据校验 → 主体与跨字段一致性校验 → 事实状态 → 规则/下游使用 → 诊断与评测

各层使用稳定契约连接，不允许解析器、Prompt、模型返回和业务表结构直接彼此耦合。

### 3.1 原始结构保真

- 同时保留文本、段落、表格单元格关系、页面、坐标、标题层级和读取顺序；
- 合并单元格、跨页表格、左右栏、值在标签左侧、表头和值错位等结构不得在预处理阶段被无声压平；
- OCR 文本必须保留置信度和原图定位信息；
- 清洗后的文本不能覆盖原始解析结果，二者分别版本化保存；
- 文件不可读、局部不可读和内容为空分别记录。

### 3.2 语义候选而非模板定位

- 候选由目标事实定义、主体类型、关系、上下文窗口和结构边界共同生成；
- 同时存在“总体结论”“分项意见”“岗位支持意见”等相似内容时，按目标事实语义和证据范围选择，不按最后一条、最长一条或首次命中选择；
- “拟任人选信息准确”中的“拟任人选”只是对象称谓，不能因包含“拟任”就推导出任职意图或职位；
- 否定、双重否定、条件、例外、时间范围和他人信息必须与目标主体绑定；
- 多候选无法可靠消歧时输出冲突或待确认，不得任意选一个。

### 3.3 快速路径门禁

确定性快速路径可以提高速度，但必须同时满足：

1. **高精度**：触发条件具有明确结构或类型约束，反例测试证明误报率可接受；
2. **可定位**：结果携带页码、结构块、原文片段或坐标；
3. **可校验**：输出进入与模型结果相同的类型、枚举、证据和一致性门禁；
4. **失败可降级**：未命中、歧义或校验失败时转交语义模型，不返回伪默认值；
5. **不阻断模型**：快速路径不能因为局部解析异常而阻止模型处理其他字段；
6. **可观测**：记录触发规则、版本、命中/拒绝原因和耗时。

正则、词典和结构规则可用于字符清洗、候选生成、类型解析、同义归一和证据校验；不得把它们扩展成对现实语言的穷举式业务理解器。

## 4. 规范字段与输出契约

每项事实定义至少包括：

|属性|说明|
|-|-|
|事实编码与版本|稳定机器编码，不依赖页面文案|
|中文名称与语义定义|明确它是什么、不是什么|
|主体与关系|本人、配偶、机构、合同方、供应商等|
|数据类型与基数|字符串、日期、金额、枚举、对象、列表及一对一/一对多|
|允许值与同义映射|规范枚举、中文/英文/缩写/历史值映射|
|缺失与空白语义|未提及、明确空白、不可读、冲突的区别|
|证据要求|页码、原文片段、坐标、来源文件及最小充分证据|
|校验约束|格式、范围、主体、时间、跨字段一致性|
|风险与人工条件|何时允许自动确认，何时必须人工处理|

任务必须绑定已发布且不可变的事实结构版本。字段增删、类型变化、枚举变化、同义映射和证据要求变化均按兼容性规则发布新版本，并定义缓存失效、历史数据、重算和下游影响。

## 5. 模型输出接入与兼容

大模型回复不稳定是正常工程事实。不同模型或同一模型不同请求可能返回 JSON 对象、数组、Markdown 代码围栏、工具调用参数、额外解释、不同键名、大小写、层级、顺序、空值或枚举同义词。系统不得假设模型永远严格遵守一个示例。

统一接入层按以下顺序处理：

1. 识别工具调用、纯 JSON、围栏 JSON 和允许的受控文本载体；
2. 严格解析失败时执行有边界、可审计的语法修复；修复失败保留结构无效状态，不猜测业务值；
3. 根据版本化别名表映射字段名，兼容大小写、下划线/驼峰、中文名和已批准历史名；
4. 处理对象与列表的允许变体，但不得把多个对象无依据合并为一个对象；
5. 执行安全类型转换和日期、金额、布尔、枚举、单位标准化；
6. 未知字段记录并忽略进入业务层，不能因额外字段导致整个响应失败；必需字段缺失则形成字段级失败；
7. 校验证据是否真实存在于对应原材料及定位范围，校验事实主体、关系、否定和时间范围；
8. 执行跨字段、跨材料一致性检查，保留冲突来源；
9. 逐字段生成状态、置信依据、拒绝原因和版本元数据；
10. 只有通过门禁的规范化事实才能进入规则引擎和自动业务流程。

### 5.1 禁止的输出处理方式

- 用 `result[0]`、最后一项或第一个键作为固定业务含义；
- 只因 JSON 可解析就认为事实正确；
- 将未知枚举静默映射为最常见值；
- 将缺失字段自动填成“否”“无”“0”或空字符串；
- 模型返回证据文字但无法在原材料定位时仍标记已确认；
- 为某一模型的偶发写法在业务代码中不断增加散落分支；
- 一条字段异常导致整份文件已经成功的其他字段全部丢失。

### 5.2 建议事实状态

项目可按业务命名，但至少区分：

|状态|语义|
|-|-|
|已找到且证据通过|值、主体和证据均通过校验|
|未找到|已完成可用内容检索但未发现该事实|
|明确空白|材料存在对应栏位且明确未填写|
|不可读|材料或局部内容无法可靠读取|
|冲突|存在多个相互矛盾且无法自动消解的证据|
|结构无效|模型输出载体无法按契约解析|
|校验拒绝|模型给出候选值但证据、类型或一致性门禁未通过|
|待人工确认|风险策略要求人工处理|
|技术失败|网络、模型、程序、超时或依赖故障|

## 6. Prompt 与模型调用设计

- Prompt 说明事实语义、主体、允许状态、输出结构和证据要求，不以单一模板示例暗示固定位置；
- 示例同时包含正例、反例、否定、缺失、冲突、同义表达和结构变化，避免只展示“标准答案格式”；
- 将大批互不相关字段按语义域分组，控制上下文长度和相互干扰；
- 模型只产生候选事实和解释，不隐藏最终业务规则；
- 记录模型实际标识、部署、参数、Prompt版本、事实结构版本、输出解析器版本和调用耗时；
- 模型升级、别名漂移或 Prompt 变更必须运行固定回归集与独立留出集，不能只比较少量示例；
- 模型不可用或返回结构异常时按字段/文档隔离失败，执行已设计的重试、备用模型或人工降级，禁止无限重试。

## 7. 兼顾速度与兼容性

语义分析为主不等于每个字段都重复调用模型。性能优化应位于公共机制：

- 一次保真解析，多事实共享结构块和证据索引；
- 用高精度快速路径处理明确标签和基础类型，其他候选交给模型；
- 按语义域批量抽取，限制单次字段数和材料窗口；
- 并发受模型、网络、限流和数据一致性约束，记录队列与调用耗时；
- 缓存键至少包含材料内容哈希、解析器版本、事实结构版本、Prompt版本、模型实际标识和标准化版本；
- 只重试失败字段或失败阶段，已成功且版本兼容的结果不重复计算；
- 性能优化不得绕过证据校验，不得以降低未知材料兼容性换取演示样例速度。

## 8. 评测集与问题空间

评测不能只使用一套标准模板。每个重要材料类别应设计多套内容语义一致但结构明显不同的材料，并保留独立留出集。最低变化轴包括：

- 段落、表格、标签、清单、混合布局和扫描/OCR；
- 字段顺序、值在标签左/右/上下、合并单元格、跨页和重复表头；
- 同义字眼、简称、英文/中文枚举、口语与正式表述；
- 主体切换、指代、配偶/关联方、多对象和跨材料关系；
- 肯定、否定、双重否定、条件、例外、范围和时间变化；
- 缺失、明确空白、不可读、冲突、重复和非法值；
- 与目标字段相似但语义不同的反例；
- 模型输出的字段别名、顺序、层级、对象/数组、围栏、额外字段、枚举和空值变体；
- 模型超时、限流、半截响应、非 JSON、单字段失败和并发场景；
- 历史正常材料和真实问题去敏后的结构变体。

应使用变形测试验证：只改变版式、字段顺序或同义表达时，规范事实应保持不变；改变主体、否定、日期范围或关键数值时，相应事实必须变化。

## 9. 指标与验收

按风险分别设置总体和关键字段阈值，至少统计：

- 字段级精确匹配或业务等价准确率；
- 必填/关键事实召回率和误报率；
- 主体与关系绑定准确率；
- 原文证据定位准确率和证据充分率；
- 状态区分准确率，尤其是未找到、明确空白、不可读和冲突；
- 模型输出结构接入成功率、修复率、拒绝率及拒绝原因；
- 自动确认率、人工确认率及人工纠错率；
- 文档成功率、字段隔离失败率、重试成功率；
- P50/P95时延、模型调用量、成本和并发稳定性。

“页面出现字段”“模型返回JSON”“一套材料全通过”不能作为能力验收。必须进行逐字段真值核对、证据核对、规则输入核对和完整端到端验证。

## 10. 可观测性、诊断与隐私

每次运行应能够按任务、材料内部ID、阶段和字段关联：

- 解析器、模型、Prompt、事实结构、输出解析器和标准化版本；
- 输入结构摘要、页数、表格/块数量、输出键与类型摘要；
- 快速路径或模型来源、证据位置、拒绝与降级原因；
- 重试次数、各阶段耗时、异常类型、稳定指纹和不含局部变量的代码调用栈；
- 缓存命中、失效和重算原因。

诊断包默认不得包含材料正文、原始模型回复、Prompt、密钥、局部变量或可识别个人信息。确需保留原始响应用于受控复现时，必须经过数据授权、加密、最小权限、保存期限和审计设计，并与普通诊断下载隔离。

## 11. 缺陷治理

发现错误时，必须按 `docs/00-项目治理/系统性问题解决方法论.md` 执行。将症状归入以下公共问题类别之一或提出新的有证据类别：

- 原始结构丢失；
- 语义候选选择错误；
- 主体、关系、否定或范围理解错误；
- 模型输出载体或字段映射不兼容；
- 类型、枚举或状态标准化错误；
- 原文证据或跨字段一致性门禁缺失；
- 缓存、版本、重试、并发或状态传播错误；
- 页面展示与内部规范值边界错误。

每个真实缺陷去敏后至少保留原失败基线、同类结构变体、易误判反例和历史正常案例。不能把“增加一个关键词/正则”直接作为根因；只有当它属于有边界的结构信号、标准化或校验机制并通过问题空间矩阵时，才可作为实现的一部分。

## 12. 开发与发布检查表

- [ ] 事实结构、主体关系、状态和证据契约已版本化；
- [ ] 原始结构保真，未把固定模板位置作为业务事实依据；
- [ ] 语义模型承担开放文本理解，确定性代码承担解析、标准化、校验和业务规则；
- [ ] 快速路径满足高精度、可定位、可校验、失败可降级、不阻断模型和可观测；
- [ ] 模型输出统一接入层覆盖字段名、枚举、层级、顺序、空值、额外字段和结构异常；
- [ ] 每项自动事实均有可定位证据，主体、否定、时间范围和跨字段一致性已校验；
- [ ] 字段级失败可隔离、重试和人工处理，不无故丢失其他成功结果；
- [ ] 缓存键和重算策略包含全部影响结果的版本；
- [ ] 多套异构材料、模型输出变体、反例、历史正常样本和独立留出集已评测；
- [ ] 逐字段真值、证据、规则输入、页面及下游结果完成端到端核对；
- [ ] 诊断信息足以定位阶段、字段和代码调用链，同时满足隐私边界；
- [ ] 已明确当前证据能证明和不能证明的兼容范围，未声称未知材料100%准确。
