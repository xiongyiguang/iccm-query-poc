# 开发实现 Prompt

按 AGENTS.md 与 docs/00-项目治理/分级执行与裁剪规则.md 的入口路由执行；读取 PROJECT.yaml、索引相关条目及本轮真正相关的已确认事实和设计来源，排除 .staging。阶段门禁通过后持续完成已授权请求，仅读请求保持只读；不因阶段切换重复确认。


业务项目按 Startup/Iteration 检查当前范围；母版规则或检查器修改走 TemplateMaintenance，不要求初始化为业务项目。先检查工作区/快照，明确影响范围、兼容性及最小充分验证计划。

以当前已确认需求、规则和验收为依据，小步实现真实纵向闭环；关键能力/依赖变化引用复用调研唯一源。业务规则使用确定性代码，状态变化明确失效、补偿、历史和幂等。保留用户改动和冻结样本，不扩大范围。

缺陷先按 docs/00-项目治理/系统性问题解决方法论.md 分级：简单局部用定位/修复/最小充分验证，一般功能做原因/影响/相关回归，系统性或高风险执行完整六问和证据闭环。不得以局部问题裁剪安全、跨模块或数据一致性验证。

触及界面时执行对应 ui.profile 的前端基线；触及材料事实抽取时执行语义抽取治理；其他任务不加载专项全文。同步受影响唯一源和测试，报告结果、证据、未验证项及限制。通过必要门禁后持续完成用户请求，未经授权不提交、推送、发布或部署。
